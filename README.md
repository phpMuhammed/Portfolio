# Mohammed Ayman Musabeh — Portfolio

Static, bilingual (English / Arabic) single-page portfolio built with Astro, TypeScript and Tailwind CSS. Zero client JS by default — a few small script islands handle the theme toggle, language toggle, mobile nav and scroll-spy.

## Running locally

```sh
npm install
npm run dev
```

The dev server runs at `http://localhost:4321`. English lives at `/`, Arabic at `/ar`.

```sh
npm run build    # production build to ./dist (fails if the CV PDF is missing — see below)
npm run preview  # serve the production build locally
npm run astro check  # TypeScript / Astro diagnostics
```

## Editing content

All copy lives in two typed data files, both implementing the same `SiteContent` interface in `src/content/types.ts`:

- `src/content/en.ts` — English copy
- `src/content/ar.ts` — Arabic copy

Because both files share one interface, the TypeScript compiler will flag it if a field is added to one language and forgotten in the other. Components never contain hardcoded copy — they just render whichever `SiteContent` object they're given (`src/pages/index.astro` passes `en`, `src/pages/ar.astro` passes `ar`).

To edit a work entry, a skill group, the hero line, etc., edit the corresponding field in both `en.ts` and `ar.ts`.

Notes on the Arabic content:

- Numbers, dates, technology names and URLs are kept in Latin script, per regional convention.
- Some spans (dates, phone numbers, metric badges) are wrapped with `dir="ltr"` or `<bdi dir="ltr">` in the components so Latin/numeric substrings don't get visually reordered by the browser's bidi algorithm inside RTL text — don't remove those wrappers when editing.

## Swapping the CV PDF

The real CV should live at:

```
public/cv/Mohammed_Ayman_Musabeh_Senior_Full_Stack_Developer_CV.pdf
```

Just replace the file — the filename must stay the same since it's referenced (with the `download` attribute) from the hero and contact sections.

`npm run build` runs a `prebuild` check (`scripts/check-cv.mjs`) that fails the build if this file is missing, so a dead download link can never ship. Until you drop in the real CV, the file present in the repo is a **placeholder PDF** generated by `scripts/generate-placeholder-cv.mjs` — it's clearly labeled as a placeholder inside the PDF itself. Replace it before deploying.

## Dropping in real project logos

By default each "Selected Work" card shows a generated lettermark (first letter of the project name on its accent colour). To use real logos instead, drop files into `public/logos/`:

```
public/logos/istoria.svg     (or istoria.png)
public/logos/onestudio.svg   (or onestudio.png)
public/logos/darent.svg      (or darent.png)
public/logos/captab.svg      (or captab.png)
```

`src/components/LogoMark.astro` checks for these exact filenames at build time (SVG first, then PNG) and falls back to the lettermark automatically if a file isn't present — no code changes needed. See `public/logos/README.txt` for the same instructions in-place.

## OG images

`public/og-en.png` and `public/og-ar.png` (1200×630) are generated by `scripts/generate-og.mjs` (via `npm run generate-og`), which rasterizes an inline SVG with `sharp`. Re-run that script if the name/title copy changes.

## Deploying

This is a fully static site (`output: 'static'` in `astro.config.mjs`) — the `dist/` folder from `npm run build` can be deployed as-is to Vercel, Netlify, GitHub Pages, or any static host, with no server runtime required.

The `site` value in `astro.config.mjs` and the `Sitemap:` line in `public/robots.txt` are set to the production domain (`https://mhmd-musabeh.vercel.app`), used for canonical URLs, `hreflang` tags, the sitemap and Open Graph image URLs.

### Vercel / Netlify

Build command: `npm run build`. Output directory: `dist`. No environment variables required.

### GitHub Pages

Set `site` (and `base`, if deploying to a subpath like `username.github.io/repo`) in `astro.config.mjs`, then build and publish the contents of `dist/` to the `gh-pages` branch (or use Astro's GitHub Pages deploy action).
